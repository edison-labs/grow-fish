# 《大鱼吃小鱼》V0.1 独立测试执行记录 R1

## 1. 测试结论

**R1 不通过，不建议产品验收。**

R1 候选可以安装依赖、构建、启动核心逻辑并提供 Web 静态交付，但独立对抗测试发现 31 个唯一缺陷：S1 1 个、S2 14 个、S3 16 个。危险出生可在激活后 0.8 秒内致死，且存在刷新批次、同级弹开、safeArea、初始水草、连吃边界、音频生命周期、性能统计、平台回退和关键视觉反馈等偏差。

本轮没有微信开发者工具、合法 AppID、目标真机或可连接的浏览器实例。因此真机功能、兼容、音频/震动、性能、内存、30 分钟稳定性和人工可用性均记为 **Blocked**，不是 Passed。即使全部代码级缺陷修复，这些外部门禁完成前也不能宣称项目已达到最终可用或已上线。

## 4. 关键独立证据

### 4.1 R1 基础门禁可运行

- `npm ci` 成功。
- 独立执行 R1 原 `npm run verify`：24/24 Node 测试通过，debug build 与微信 bundle smoke 通过。
- 独立计算配置哈希为 `1768c34e`；初始构建文件哈希与正式提测单相同。
- 本地静态服务返回：`/` 200、`/app.js` 200、`/missing.js` 404，MIME 分别为 HTML、JavaScript、plain text。

### 4.2 原门禁未覆盖的高风险失败

- seed `41233` 的危险鱼被安全算法接受后约 0.467 s 造成死亡；根因是预测遗漏生产运动中的 y 正弦漂移。
- seed `20260731` 的一个 spawner tick 同时激活 pending 并新增另一条鱼，违反每 tick 最多一条。
- seed `314159` 的同级碰撞把玩家冲量写入速度，但下一 tick 在位移前清零，玩家没有可见分离。
- hide/show 后 30 s 墙钟进入 FPS/P95，并触发 dropped tick；观测窗仅 600 帧，无法代表连续 60 s。
- 21:9 合法安全区开局 seed `951` 只有 5 株激活水草；safeArea 顶部按钮仍位于 inset 外。
- 恰好 3.000 s 的第二次吞食被错误重置连吃。
- 代码盘点确认 HUD 数字、升级文字、猎物吸入、升级环、通关庆祝、死亡慢动作、连吃拖尾、玩家游动状态和水草外观多样性缺失或时长不符。
- 20 次同刻短音创建 20 个 oscillator，没有技术方案规定的并发上限 6。

详细 seed、tick、步骤、期望/实际和影响域见 `docs/bugs-r1.md`；自动回归见 `tests/qa-r1-regression.test.js`。

## 6. R2 回归入口

研发提交 R2 后，测试必须：

1. 记录新的版本标识、配置哈希、debug/release 两套 SHA-256 和修复影响范围。
2. 独立执行最终冻结的 41 项 QA 定点门禁以及完整 `npm run verify`。
3. 对危险安全算法执行 100+ seed 的生产参数属性测试；对鱼边界同时回归 resize、入场、离场与危险 suppression。
4. 构建 release 并扫描 `__growFishDebug`、`TestHarness`、source map、外部网络 API/地址和未知资源引用；再重建 debug 并校验最终 SHA。
5. 用 Canvas 行为检查反馈存在性和时长，但把最终视觉质量、声音、震动、真机兼容、性能与可用性继续保留为外部门禁。
6. 只有 R2 代码级回归全绿且外部 Blocked 项有真实证据后，测试才可输出“建议产品验收”。
