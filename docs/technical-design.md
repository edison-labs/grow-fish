# 《大鱼吃小鱼》微信小游戏 V0.1 技术方案

## 1. 文档状态与结论

- 状态：V0.1 R4 本地代码候选对应技术方案；需求基线为策划案 V0.1 与产品 D01–D25。
- 结论：采用原生微信小游戏 Canvas 2D + CommonJS 纯 JavaScript；微信端与浏览器端共享同一核心、配置和渲染器。
- 本地自动化 91/91、Debug/Release 双构建及对应微信 bundle smoke 已通过，正式 AppID 已配置；微信开发者工具、真机兼容与性能、30 分钟 soak、人工产品验收尚未完成，因此不代表正式发布。
- 非目标：DOM/CSS 玩法、第三方游戏引擎、后端、登录、广告、支付、云存档、排行和联网埋点。

## 2. 技术选型与版本基线

| 项目 | 冻结选择 |
| --- | --- |
| 微信运行时 | 原生小游戏、Canvas 2D、CommonJS，横屏 `landscape` |
| 代码 | ES2020 纯 JavaScript；核心禁止直接依赖 `wx`、DOM、墙钟和 `Math.random` |
| Node | `22.23.0`；使用内置 `node:test` / `assert`，不引入测试框架运行时 |
| 构建 | `esbuild 0.25.0` 仅作开发依赖；锁入 `package-lock.json`；输出微信与浏览器两个 bundle |
| 最低基础库 | `2.25.3`；管理后台发布时设置同一最低值 |
| 支持策略 | 微信客户端 `8.0.40+`、iOS `13+`、Android `8.0+`；实际验收同时记录 SDKVersion |
| 帧率 | 逻辑固定 60Hz；目标渲染 60 FPS，不预声明 30 FPS 发布降级档 |
| 坐标 | 玩法统一逻辑像素；Canvas backing store 使用 DPR，默认上限 2 |

低版本/能力缺失按端口降级：`getWindowInfo` 回退 `getSystemInfoSync`，无 safeArea 时使用窗口边界和 HUD 8% 安全带；无窗口监听时仅启动时适配；音频/震动失败不影响玩法。核心必须离线可玩。

```text

├── package.json / package-lock.json
├── src/
│   ├── core/                  # 状态、时钟、实体、成长、得分；无平台依赖

│   ├── input/                 # touchId 所有权、摇杆意图
│   ├── collision/             # 检测、事件缓冲、稳定排序、接触闩锁
│   ├── spawn/                 # RNG、计数、预约、预警、安全搜索
│   ├── render/                # Canvas 场景、程序化美术、HUD、特效
│   ├── platform/              # PlatformPort、wechat、browser、fake
│   ├── storage/               # schema、迁移、合并与容错
```

微信开发者工具直接导入仓库根目录；`project.config.json` 已配置项目主体提供的正式 AppID，上传与体验版操作仍需相应账号权限。`npm run preview:web` 提供浏览器同核预览；`npm run build:wechat`、`npm run build:web` 和 `npm test` 为固定入口。

## 4. 架构与依赖规则

- `GameCore` 只接收 `PlatformPort`、配置、时钟和 seed；输出不可变 `RenderSnapshot` 与结构化事件。
- `PlatformPort` 统一画布、输入、生命周期、视口、存储、音频、震动和日志；微信/浏览器/fake 三个实现。
- 渲染不回写玩法状态；表现 RNG 不得调用玩法 RNG；音频/震动只消费已提交事件。
- 配置先 schema 校验再启动；概率和、等级连续性、时间非负、池容量及公式表不合法时测试构建快速失败。

## 5. 固定步长、状态与时钟（D01–D05、D16、D24）

- 主循环使用 accumulator，逻辑步长 `1/60s`；单次真实间隔钳制 100ms、每渲染帧最多补 5 tick，超额丢弃并记录长帧，后台恢复绝不补算。
- 时钟分为 `runClock`（有效单局）、`cinematicClock`（死亡/通关表现）和 `wallClock`（只作诊断）；暂停/后台冻结前两者。
- 顶层状态为 `HOME / RUNNING / PAUSED / DEAD / WIN / RESULT`；`TUTORIAL` 与 `LEVEL_UP` 是 RUNNING 上的覆盖层。
- 教程覆盖层不阻断玩法：输入、AI、碰撞、得分、成长、连吃、runClock 与普通鱼刷新均照常运行。提示完成与 `tutorialCompleted` 分开管理。
- 升级覆盖层持续 0.3 秒；等级立即生效，输入、AI、碰撞、奖励、计时与普通鱼刷新均照常运行，仅升级后的 2 个有效游戏秒禁止新预约 P+2；成长只缓存，覆盖层结束后的下一 tick 才可再升一级。
- 无敌 0.8 秒、P+2 新预约保护 2 个 runClock 秒；无敌重叠鱼标记 suppression，必须先完全分离再重入才致死。
- 升至 Lv.10 的 tick 立即幂等锁定 WIN，停止 runClock/碰撞/刷新；1.2 秒后单次进入 RESULT。
- onHide：RUNNING/PAUSED 冻结并返回暂停页；DEAD/WIN 已锁结果则 onShow 直接安全进入 RESULT；HOME/RESULT 保持。

每 tick 顺序固定：应用 tick 输入 → 更新覆盖层/保护/计时 → 玩家与既有 AI 移动 → pending 预警/激活 → 刷新决策 → 收集碰撞 → 稳定排序并提交 → 统一成长/状态转移 → 回收 → 输出快照与 trace。

## 6. 输入、移动与适配（D09–D10）

- touchStart 时按坐标把每个 touchId 永久分配给 UI 或 MOVE；MOVE 只接受第一有效指，结束后不接管第二指；UI 可用第二指暂停。
- UI 起点移出仍属 UI，移出按钮取消点击；场景起点移入 UI 仍属 MOVE；touchcancel 按 0.2 秒释放减速处理。
- 摇杆中心为按下点，`R=短边×8%`，死区 `0.15R`，比例为策划公式；拖动中以 `1-exp(-dt/0.12)` 插值目标速度。
- 松手保存释放速度并线性平滑到 0，`t=0.2s` 精确归零；暂停/后台清空所有 touchId 和速度，恢复后必须重新按下。
- 边界以碰撞椭圆外沿为准：钳制位置，仅清除向外法向速度，保留切向速度。
- 视口支持 4:3–21:9、左右横屏、平板和折叠展开态；HUD 高度 `max(8%H, safe inset)`，并避让胶囊区域。
- 横屏 resize 自动暂停，按旧/新活动区归一化映射并合法夹取对象；竖屏仅显示旋转提示，回横屏由玩家主动继续。

## 7. 碰撞、成长与结算（D04–D05、D14–D16）

- 只检测玩家—野生鱼、玩家—水草；野生鱼互不碰撞。采用轴对齐椭圆，主体宽高各取可见鱼身 70%，尾鳍/装饰不参与。
- 帧首冻结玩家等级和无敌状态；检测阶段只写入预分配事件缓冲，不在遍历中修改实体。
- 排序为：致命鱼 → 可食鱼 → 水草 → 同级；同类按 spawnSeq 升序。任一致命成立则本 tick 其他吞食全部取消。
- 可食鱼按稳定顺序更新连吃和分数；水草不开始、不延长、不打断连吃；统一累加 XP 后每 tick 最多升级一次。
- 多个致命对象同 tick 时取最小 spawnSeq 作为结算“被 Lv.X 鱼吃掉”；结果、存储和事件提交均有一次性锁。
- 同级弹开沿碰撞法线；中心重合时用实体 ID 推导固定法线；同一鱼 generation 冷却 0.5 秒，池复用必须重置。
- 升级视觉可超调 5%，碰撞体只平滑至新配置尺寸、不跟随表现超调；active 危险鱼的红色闪烁轮廓在下一 tick 按新关系刷新，鱼的固定等级素材不因玩家升级而改变。

## 8. 刷新、预警与安全算法（D06–D08、D15、D21–D23）

- 主 seed 派生 `gameplay / appearance / fx` 三个 32 位 RNG 子流；核心禁用 `Math.random`。实体使用单局单调 spawnSeq，池 generation 防旧接触泄漏。
- 初始玩家位于活动区 `(35%W, 50%H)`；生成 6 草、其中至少 2 株在 1.0–2.5 玩家宽合法环带；放置 4 条可见 Lv.1，距玩家至少 1.5 玩家宽，零致命鱼。
- 玩家获得控制权时同一刷新器立即开始补齐，教程覆盖层不阻断刷新；每个逻辑 tick 最多预约 1 鱼。每局 runClock 前 5 秒先把绝对等级过滤为 Lv.1/Lv.2，再归一化权重。
- 每次决策重算：active、pending、edibleActive、lethalReserved、pPlus2Reserved、左右 enteringReserved。总数/危险/P+2/侧边配额含 pending；可食最低数为 `ceil(Target/2)` 且只计 active。
- 若可食数不足，下一次成功预约强制可食；危险/P+2/同侧配额满则去除对应候选；权重为空或位置失败只延迟，不越过硬约束。
- 危险预约 t=0 即锁定 level/side/y 并占配额，显示 0.5 秒预警；期间不可见、不移动、不碰撞；到时从完整屏外激活。暂停冻结预警，升级后激活前重算关系。
- 鱼位置最多尝试 5 次；失败延迟 0.2 秒。激活前再次验证玩家距离，失效则取消并重新预约，禁止贴脸强刷。
- 安全出生采用连续相对运动 swept-ellipse TOI：候选与玩家按当前速度预测，最早接触必须 `>=0.8s`。
- 同时采样玩家 8 个可达逃生方向，以固定步模拟 0.8 秒并考虑边界、现存/即将激活致命鱼；至少一条路径全程无碰撞且终点保留 0.25 玩家宽净空，否则换 y/side 或延迟。
- 补草最多 8 点：有移动方向时搜索 ±60°、1.5–3.0 玩家宽；静止取最后朝向，再扩展全圆；失败延迟 0.5 秒。只有长成且在可视活动区的草算可见。
- `SpawnDecisionTrace` 记录 tick、seed 游标、原始/裁剪权重、计数、保护、候选、尝试位置、安全拒绝和最终结果。

## 9. 渲染、音频、震动与存储（D11–D13、D17–D20）

- 单上屏 Canvas；静态背景和重复形状可缓存到离屏 Canvas。Lv.1–Lv.10 由等级唯一映射到十套固定程序化素材，每级同时使用不同的颜色、主体轮廓、鳍尾和纹样，不以矩形灰盒验收，也不允许表现随机改变鱼的等级素材。
- 玩家和野生鱼的主体宽度都使用 `min(0.16W, 0.08W × 1.08^(level-1))`，高度按统一宽高比缩放；尺寸严格逐级增大，Lv.10 约为 Lv.1 的 2 倍。玩家与同级野生鱼使用同一素材，玩家仅用细描边及待机、游动、吞食、死亡动效表明控制归属。
- 实战鱼身旁不绘制 `Lv.X`、“可吃”或“同级”等文字/符号标记；只对 `fish.level > player.level` 的 active 野生鱼绘制不完全消失、按实体错相位的红色闪烁主体轮廓，pending 危险鱼继续使用现有屏幕边缘预警。教程不再给目标鱼挂“可吃”标签，底栏只说明体型更小的鱼可吃、红色闪边鱼危险。
- RUNNING HUD 右上角新增程序化鱼形图鉴按钮，位于暂停键左侧并避让 safeArea 与微信胶囊。点击后以 `pauseView=CATALOG` 进入 PAUSED 并冻结输入、AI、碰撞、刷新、预警和全部游戏计时；关闭图鉴清空输入后恢复 RUNNING。
- 图鉴使用安全区内居中的模态面板，以 `5×2` 无滚动卡片按 Lv.1–Lv.10 排列；每卡使用 `FISH_LEVEL_VISUALS` 的名称和固定素材，并按 `playerSizeScale(level) / playerSizeScale(10)` 展示相对体型。实战禁用鱼身等级不限制图鉴显示 `Lv.N`；图鉴不得显示随玩家变化的可吃/同级关系。
- `fish_eaten` 表现事件携带猎物等级；缩小吸入动画按该等级重新绘制同一套颜色、轮廓、鳍尾和纹样，不允许退回默认鱼素材。
- 音频仅在开始按钮等用户手势后启动；构建阶段生成原创本地 WAV，短音优先 WebAudio、回退 InnerAudio；实例复用、并发上限 6，死亡/通关优先。失败静默且保留视觉反馈。
- 震动经 HapticPort 调用，能力/强度不支持或系统禁用时静默降级；开关默认开启并即时持久化。
- 存储 key 为 `growFish.save.v1`：`schemaVersion`、highestScore、highestLevel、fastestWinMs|null、tutorialCompleted、soundEnabled、hapticEnabled。
- 读取按字段校验回退；最高值取 max、最快仅成功局取原始毫秒 min、并列不覆盖；放弃局不更新。写失败保留内存值、提示“记录未保存”，不阻断结果。
- V0.1 不发网络埋点；事件总线仅写本地环形日志和测试报告。程序化资源及生成脚本随仓库交付，记录原创来源。

## 10. 调试、自动化与提测接口（D22、测试门禁）

- `TestHarness.set/resetSeed`、读取各 RNG 游标；`pauseClock/stepTicks/stepDt`；读取逻辑 tick 和配置 hash。
- 可设置玩家 level/XP/score/combo/invincible/state，创建指定鱼/草，注入同 tick 碰撞集合，冻结 AI。
- 可读 active/pending/edible/lethal/P+2/左右 entering、完整 SpawnDecisionTrace、碰撞排序和结果锁。
- 可显示碰撞体、活动区、safeArea、摇杆 R/死区、实体 ID/generation；可读每类池创建/借还/活跃/峰值。
- FakePlatform 可注入 onHide/onShow/resize、存储缺失/脏数据/写失败、音频/震动失败；支持存档清空/导入/导出。
- Node 测试覆盖公式、状态、同帧优先级、seed 复现、刷新属性、池复用、存储迁移和 100 局无渲染模拟；相同版本/config/seed/tick 输入必须产生相同事件日志。
- 浏览器预览使用 BrowserPlatform 和同一 CanvasRenderer；只替换平台端口，不复制玩法。微信真机项目仍由测试计划单独验收。
- `DEBUG_TOOLS` 构建常量控制测试面板；发布 bundle 经死代码消除后不可触达，玩法代码与提测版保持相同。

## 11. 性能、准出与发布边界（D25）

- 池化鱼、草、预警、飘字、气泡和粒子；玩家对约 14 条鱼/8 草做 O(n) 检测；热路径使用预分配缓冲，禁止逐帧临时数组/闭包。
- 目标 60 FPS：最低支持真机连续 60 秒平均 ≥50 FPS、P95 帧间隔 ≤33.3ms、无 >200ms 玩法卡顿；加载后 onShow 到首页可交互 ≤3 秒。
- 连续 10 局后活跃对象/监听器无增长，内存增量不超过首局稳定基线的 10% 或 20MB（取更宽者），无崩溃、黑屏和输入失效。
- 调试面板提供滑动窗口 FPS/P95/长帧、池统计和掉帧原因；最终以微信真机性能面板与测试报告为准。
- 研发准入顺序：配置/核心单测 → 浏览器闭环 → 微信工具导入 → 研发自测 → 正式提测 → 缺陷回归 → 测试报告 → 产品验收。
- 本机已完成 91/91 自动化、Debug/Release 双构建及对应微信 bundle smoke，正式 AppID 已配置；微信开发者工具、体验版、真机兼容与性能、30 分钟 soak、人工产品验收、审核与线上发布仍是外部门禁，未经完成不得宣称已发布。
