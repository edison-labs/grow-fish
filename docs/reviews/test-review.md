## 3. 已确认且可直接验收的口径

以下规则明确，可作为默认验收基线：

1. 游戏为微信小游戏、横屏、单局制；玩家由 Lv.1 成长至 Lv.10 后立即通关。
2. 输入为任意空白位置的相对拖动，不是鱼追随手指绝对坐标；UI 触摸优先于移动。
3. 水草为 0 级食物；低等级鱼可吃、同等级弹开、高等级鱼致死；无敌时穿过高等级鱼。
4. 同帧顺序为：UI/暂停 → 致命碰撞 → 低等级鱼 → 水草 → 同级弹开 → 统一成长结算；致命成立后停止本帧吞食。
5. 成长溢出保留，单帧最多升一级；升级有 0.8 秒无敌和 2 秒 P+2 刷新保护。
6. 玩家体积、速度、成长、得分、连吃均有公式；野生鱼概率必须服从场上硬约束。
7. 致命鱼从屏外生成，并在进入前提供 0.5 秒边缘预警；P+2 最多 1 条；致命鱼最多 1–3 条。
8. 暂停冻结时间、AI、刷新和连吃窗口；后台返回默认保持暂停。
9. 死亡、通关只能结算一次；本地记录最高分、最高等级和最快通关时间。
10. 首版明确排除广告、支付、复活、登录、云存档、排行榜和复杂系统。

| 致命鱼上限 | 1, 1, 2, 2, 2, 3, 3, 3, 3 |

边界权重预期：

- P=2：Lv.1/Lv.2/Lv.3/Lv.4 = 65%/15%/17%/3%。
- P=9：Lv.7/Lv.8/Lv.9/Lv.10 = 20%/45%/15%/20%。
- P=10：立即通关，不再抽取或刷新野生鱼。

上述“可吃鱼最低数量采用向上取整”已由产品 D06 确认为唯一口径。

## 7. 可测性与研发提测接口要求

以下不是玩家功能，但缺失会使概率、边界和同帧规则无法低成本验证，建议作为研发完成定义的一部分：

1. 可设置、读取、重置玩法 RNG seed；玩法、外观、粒子各自独立子流。
2. 可暂停自动时钟并以指定 `dt` 单步推进，能输出逻辑帧号。
3. 可创建指定等级/位置/方向/速度的鱼和水草，并注入同一帧碰撞集合。
4. 可设置玩家等级、成长值、分数、连吃、无敌剩余时间和状态。
5. 可查看刷新决策 trace：候选权重、被移除权重、保护窗口、计数、最终等级、侧边、位置失败原因。
6. 可读取 `liveFish`、`edibleFish`、`lethalFish`、`pPlus2Fish`、左右侧 entering 数量及 pending warning。
7. 可显示碰撞体、活动边界、安全区、摇杆死区/半径、对象 ID 和关系等级。
8. 可读取对象池每类创建/借出/归还/活跃/峰值数及每帧分配、GC/长帧指标。
9. 平台 API 经适配层封装，可 mock 前后台、窗口尺寸、安全区、存储成功/失败、音频和震动。
10. 可清空、导入和导出本地记录；脏数据测试不依赖人工修改手机文件。
11. 关键事件使用结构化日志：状态变化、碰撞收集/排序/处理、升级、死亡/通关锁、刷新和存储。
12. 测试构建与发布构建共用玩法代码；调试面板必须由构建开关完全排除或不可从生产入口访问。

## 8. 主要质量风险排序

| 风险 | 概率 | 影响 | 优先控制 |
| --- | --- | --- | --- |
| 随机约束只在“抽取时”生效，回收/pending 计数错误导致超上限 | 高 | 致命、不公平死亡 | 决策 trace + 长时间属性测试 |
| 碰撞回调遍历顺序不同导致同帧结果不同 | 高 | 规则错误、难复现 | 碰撞事件队列 + 固定排序 + seed 回放 |
| 前后台/暂停仍推进计时器或碰撞 | 高 | 非可解释死亡、记录错误 | 统一游戏时钟 + 生命周期真机测试 |
| 多触点或 UI 触摸泄漏为移动输入 | 中 | 操作失控 | touchId 所有权状态机 |
| resize/safeArea/DPR 混用使边界、UI 或速度失真 | 中 | 兼容性严重 | 逻辑视口统一 + 真机矩阵 |
| 对象池复用状态未清理产生隐形碰撞、重复得分或错误等级 | 高 | 功能严重 | 池生命周期契约 + 百轮模拟 |
| 本地数据损坏或最快时间以 0 初始化 | 中 | 留存记录错误 | schema 校验 + 故障注入 |
| 音频/震动调用失败阻塞或抛错 | 低 | 稳定性/体验 | 平台适配层静默降级 |
